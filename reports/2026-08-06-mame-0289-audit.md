# MAME 0.289 audit — 2026-08-06

**Scope:** full read of [`whatsnew_0289.txt`](https://www.mamedev.org/releases/whatsnew_0289.txt)
(~4,600 lines), cross-checked against a fresh snapshot of all 172
`Arcade-*_MiSTer` repos (~1,040 `.mra` files across 169 repos that publish
them) and all ~810 `.mra` files in `MRA-Alternatives_MiSTer`. This was the
first run against this MAME version; nothing carried over from a prior audit.
Every finding below marked "confirmed" was checked against MAME's live driver
source on GitHub (`raw.githubusercontent.com/mamedev/mame/master/...`), not
just the changelog's prose.

---

## Confirmed breakage — needs an `.mra` update

### 1. TwinBee (Bubble System) — `Arcade-BubSys_MiSTer`

- **Changelog:** `-nemesis: add bs_ prefix to bubsys games, mark bs_rf2 a not working [hap]` (0.289, source changes).
- **What actually changed** (verified in `src/mame/konami/nemesis.cpp`): all
  four Bubble System titles were pulled out from under the plain `nemesis.cpp`
  romset and reparented under a new BIOS-root machine:

  | Old (pre-0.289) | New (0.289+) | Parent |
  |---|---|---|
  | `twinbeeb` | `bs_twinbee` | `bubsys` ("Bubble System BIOS", `MACHINE_IS_BIOS_ROOT`) |
  | (gradius bubble variant) | `bs_gradius` | `bubsys` |
  | (galactic warriors bubble variant) | `bs_gwarrior` | `bubsys` |
  | — (new) | `bs_rf2` | `bubsys` — newly promoted to working this release |

- **What MiSTer has now:** `Arcade-BubSys_MiSTer`'s only release,
  `TwinBee (Bubble System).mra`, still declares:
  ```
  <setname>twinbeeb</setname>
  <mameversion>0266</mameversion>
  <!-- no <parent> tag -->
  ```
  targeting ROMs under the old standalone `twinbeeb` naming. Current MAME's
  `bs_twinbee` set (`src/mame/konami/nemesis.cpp`, `ROM_START( bs_twinbee )`)
  requires `boot.bin`, `twinbee.bin`, `400-e03.5l`, `400-a01.fse`,
  `400-a02.fse`, plus the `bubsys` BIOS parent's ROMs — the old flat
  `twinbeeb.zip` layout MAME tooling generates today no longer matches what
  this `.mra` expects.
- **Confidence:** confirmed against live driver source.
- **Suggested fix:** rebuild the `.mra`'s `<rom>` section against
  `ROM_START( bs_twinbee )` and its `bubsys` parent, set
  `<setname>bs_twinbee</setname>`, `<parent>bubsys</parent>`,
  `<mameversion>0289</mameversion>`.
- **Related opportunity, not a fix:** `Arcade-BubSys_MiSTer` only ships the
  TwinBee variant. `bs_rf2` ("Konami RF2: Red Fighter (Bubble System)") was
  newly *promoted to working* this release and doesn't exist anywhere in
  mister-devel yet — worth a new `.mra` if someone wants it, separate from
  the fix above.

## Already fixed, or not actually broken

### 2. Sailor Moon parent swap — `Arcade-CaveBanpresto_MiSTer` + `MRA-Alternatives_MiSTer`

- **Changelog:** `-atlus/cave.cpp: Made the Japanese Sailor Moon game the parent. (#15574) [Vas Crabb]`
- **What actually changed** (verified in `src/mame/atlus/cave.cpp`): this
  wasn't just a parent pointer flip — the **ROM content under setname
  `sailormn` moved**. Before 0.289, `sailormn` held the Europe release
  (`sailormn_europe.nv`); MiSTer's own `ArcadeDatabase_MiSTer` CSV still
  describes it that way. As of 0.289, `sailormn` is the parent and holds the
  **Japan** release (`sailormn_japan.nv`); the old Europe content moved to a
  new setname, `sailormne`.
- **`Arcade-CaveBanpresto_MiSTer` (the main core repo): already correct.**
  Its current release is `Bishoujo Senshi Sailor Moon (Version 95-03-22B, Japan).mra`,
  `<setname>sailormn</setname>`, `<mameversion>0289</mameversion>`,
  `zip="sailormn.zip"`, EEPROM CRC `ea03c30a` matching `sailormn_japan.nv` —
  correct. No action needed.
- **`MRA-Alternatives_MiSTer`: partially updated.** The three Europe-region
  variants (one per date-revision: 95-03-21, 95-03-22, 95-03-22B — setnames
  `sailormnoe`/`sailormnne`/`sailormne`) already carry `<mameversion>0289</mameversion>`
  and correct content — someone already did this half of the fix. The
  remaining region variants (Japan/USA/Hong Kong/Korea/Taiwan × all three
  date-revisions, e.g. `sailormnnj`, `sailormnu`, `sailormnh`, `sailormnk`,
  `sailormnt`, and their `o`-prefixed siblings) are still stamped
  `<mameversion>0275</mameversion>`.
  - **Verified these are not actually broken:** spot-checked `sailormnnj`
    (Japan, 95-03-22 revision) — its `<part>` CRCs (`234f1152`, `32084e80`,
    etc.) match `ROMS_SAILORMNN` in current `cave.cpp` exactly. These
    setnames were never touched by the reparent (only `sailormn`/`sailormne`
    swapped); the stale `mameversion` tag is cosmetic, not a functional break.
  - **Suggested fix:** low priority — bump `<mameversion>` to `0289` on the
    remaining ~15 non-Europe Sailor Moon alt files once someone's touching
    that folder anyway. No romset rebuild needed.
- **New finding this run:** `ArcadeDatabase_MiSTer/ArcadeDatabase.csv` (a
  third, separate repo — see mister-devel.md) still lists `sailormn` as the
  Europe version (`parent_title` / region columns unchanged since before
  0.289). This is metadata-only (doesn't drive ROM loading) but it's wrong
  and worth a PR to that repo's CSV independent of the two above.

### 3. Data East `deco32.cpp` split / `deco156.cpp` → `hvysmsh.cpp` rename

- **Changelog:** `-dataeast/deco32.cpp: Split and renaming due to hardware differences, Updates (#15726) [cam900]` — splits `captaven*` into `dataeast/captaven.cpp`, `fghthist*`/`tattass*`/`nslasher*` into `dataeast/fghthist.cpp`, `dragngun*`/`lockload*` into `dataeast/dragngun.cpp`; separately renames `dataeast/deco156.cpp` to `dataeast/hvysmsh.cpp`.
- **MiSTer coverage:** only the `nslasher` family is covered
  (`Arcade-NightSlashers_MiSTer`: `nslasher`, `nslasherj`, `nslashers`,
  `nslasheru`). `captaven`, `fghthist`/`tattass`, `dragngun`/`lockload`, and
  the `deco156`/`hvysmsh` family aren't in mister-devel at all (core repos or
  alternatives) — this driver split cannot affect anything MiSTer currently
  ships except Night Slashers.
- **Verified in `src/mame/dataeast/fghthist.cpp`:** `nslasher`, `nslasherj`,
  `nslashers`, `nslasheru` all still exist with unchanged setnames and parent
  relationships (all clones of `nslasher`). Only cosmetic changes (title
  wording, one year correction). `Arcade-NightSlashers_MiSTer`'s
  `<mameversion>0264</mameversion>` is very stale as a tag but not a
  functional break.
- **Verdict: not an issue.** No action needed beyond an optional
  `<mameversion>` bump.

read but had no bearing on arcade content MiSTer covers. Jotego-framework
cores (`Arcade-1942_MiSTer`, `Arcade-1943_MiSTer`, `Arcade-Deco156Simple_Mister`,
and any others matching that pattern — see mister-devel.md) were **not**
checked, because their `.mra`s live in `jotego/jtbin`, outside this pack's
current scope.
